# 团队求助规则

## 何时求助

先查 README、`docs/`、Issue/PR、代码上下文；仍无法判断时再求助。必须求助的场景：

- 需求、AC、范围或优先级不清。
- 多个技术方案都可行，需要 PM/负责人拍板。
- GitHub 权限不足，无法完成标签、评论、合并等操作。
- 业务预期与代码行为不一致，需要确认产品口径。
- 测试环境缺少必要依赖，需要团队提供共享环境或替代方案。

## 怎么求助

1. 先在对应 Issue/PR 评论中说明问题、已查证内容、需要谁确认。
2. 根据项目公开协作约定，在对应 Issue/PR 中提醒维护者或负责人，不依赖私有通讯渠道。
3. 同一问题不重复刷屏；等待回复。
4. 收到结论后回写 Issue/PR，保持 GitHub 为事实来源。
